# 월간 일정표

자립지원센터의 월간 「일자리 근무 일정표 및 수업계획표」를 한 번만 만들고,
참여자별 계획표를 한 번에 인쇄하는 웹앱입니다.

- 화면 = 인쇄물: 인쇄될 A4 가로 달력을 그대로 눌러서 고칩니다.
- 줄 맨 앞에 `[탁구]`를 쓰면 탁구반 사람 계획표에만 들어갑니다.
- `개인별 인쇄` 한 번으로 참여자 수만큼 A4 가로 페이지가 나옵니다.
- 입력하고 1초 뒤 자동 저장, 공휴일·대체공휴일 자동 표시(공휴일이 된 날은 일정 비움), 새 달은 지난달 요일 패턴으로 채움.
- **근무시간**: 「출근」「근무」가 들어간 줄의 시간(예: `출근(9시~12시)`)을 사람마다 받는 줄만 더해 계산. 칸마다 그날 시간, 「더보기 → 근무시간」에 한 달 합계가 고칠 때마다 바로 바뀜.
- **빨리 고치기**: 「출근 → 활동」 버튼(날짜 칸을 누르고 버튼을 누르면 출근 줄은 바뀌고 활동은 넣고 빠짐, 장소는 활동 글 아래 줄에 적어 둠, 버튼부터 누르면 여러 날짜에 같은 규칙으로 한꺼번에), 칸 도구 「이 날 지우기」, 「이 달 모두 지우기」, 자동 완성(전에 쓴 줄, `[` 치면 꼬리표), 칸 도구의 「같은 요일에 모두」, 「찾아 바꾸기」.
- **기록**: 달마다 예전 저장본(10분 간격, 최근 40개)으로 되돌리기.
- 인쇄할 사람 고르기(전원 / 반별 / 직접), 참여자 **잠시 빼기**(인쇄·근무시간에서 제외).

## 화면 위쪽

달 이동 · 저장 상태 · 「누구 계획표로 볼까요?」 · **더보기**(찾아 바꾸기, 근무시간, 기록, 참여자·설정, 사용법) · **개인별 인쇄**.
처음 쓰는 사람은 달력 칸과 인쇄만 보면 되도록, 가끔 쓰는 기능은 더보기에 넣었습니다.

## 구성

| 파일·폴더 | 내용 |
|---|---|
| `public/` | 화면 (빌드 없는 HTML·CSS·JS). `rules.js`에 꼬리표·새 달 규칙 |
| `functions/api/[[path]].js`, `lib/api.js` | 저장·로그인·공휴일 API (Cloudflare Pages Functions) |
| `lib/schema.js` | DB 표 — 처음 접속할 때 저절로 만들어짐. 처음 10월을 만들 수 있게 9월 예시도 넣음 (참여자 이름 없음) |
| `test/` | 규칙·공휴일 응답 해석 테스트 |
| `preview/` | 서버 없이 보는 시연용 한 파일 HTML (배포에는 안 들어감) |

## 배포하기 — Cloudflare 웹사이트에서만 (프로그램 설치 필요 없음)

HTML만 올리면 화면은 뜨지만, 고친 내용이 **각자 브라우저에만** 남아 동료끼리 공유되지 않습니다.
그래서 Cloudflare의 무료 DB(D1)를 하나 만들어 연결합니다. 모두 [dash.cloudflare.com](https://dash.cloudflare.com) 화면에서 합니다.
(Cloudflare 화면의 메뉴 이름은 가끔 조금씩 바뀝니다. 비슷한 이름을 찾으면 됩니다.)

**1. DB 만들기**
1. 왼쪽 메뉴 **Storage & Databases → D1 SQL Database → Create**
2. 이름 `monthly-schedule` → 만들기 (표는 앱이 처음 켜질 때 저절로 만듭니다. SQL을 붙여넣을 필요 없음)

**2. 사이트 만들기 (GitHub 연결)**
1. 왼쪽 메뉴 **Workers & Pages → Create → Pages** 탭 → **Import an existing Git repository**
2. GitHub 계정을 연결하고 이 저장소(`elc`) 선택
3. 설정
   - Production branch: 코드가 있는 브랜치 (지금은 `claude/monthly-schedule-system-v2-0id59s`, main으로 합치면 `main`)
   - Framework preset: **None**
   - Build command: **비워 둠**
   - Build output directory: **`public`**
4. **Save and Deploy**

**3. DB와 비밀번호 연결**
프로젝트 화면 → **Settings**
1. **Bindings → Add → D1 database** — Variable name `DB`, 데이터베이스 `monthly-schedule`
2. **Variables and Secrets → Add** — 종류를 **Secret**으로
   - `APP_PASSWORD` : 동료들이 쓸 비밀번호
   - `HOLIDAY_API_KEY` : 공휴일 서비스키 (아래 참고, 나중에 넣어도 됨)
3. **Deployments** 탭 → 맨 위 배포의 **⋯ → Retry deployment** (설정은 다시 배포해야 적용됩니다)

끝나면 `https://<프로젝트이름>.pages.dev` 주소가 생깁니다. 이 주소와 비밀번호를 동료에게 알려 주세요.
처음 들어가서 **참여자·설정 → 참여자**에서 명단 파일(.xlsx, .csv, .txt — 한 줄에 이름, 꼬리표)을 불러오거나 엑셀 두 칸을 붙여넣으면 됩니다.

이후 GitHub에 코드가 올라가면 Cloudflare가 **저절로 다시 배포**합니다.

### 공휴일 서비스키

1. [공공데이터포털](https://www.data.go.kr)에서 「한국천문연구원_특일 정보」 활용신청 (보통 바로 승인)
2. 마이페이지 → 활용 신청 현황 → **일반 인증키** 복사 (Encoding·Decoding 어느 쪽이든 됩니다)
3. 위 3-2의 `HOLIDAY_API_KEY`에 붙여넣고 다시 배포

키가 없거나 API가 안 되면 앱은 공휴일 없이 동작하고 상단에 「공휴일 정보 없음」이 작게 뜹니다.
받아 온 공휴일은 DB에 달마다 저장되고 일주일마다 다시 확인합니다(임시공휴일 대비).
센터 자체 휴무일은 **참여자·설정 → 기관 휴무일** 탭에서 넣습니다.

### 비밀번호

- `APP_PASSWORD`를 바꾸고 다시 배포하면 **모든 사람이 로그아웃**되고 새 비밀번호로 들어와야 합니다.
- 로그인은 30일 유지됩니다.
- 더 엄격하게 막고 싶으면 Cloudflare Zero Trust의 **Access**로 이메일 인증을 앞에 붙일 수 있습니다(코드 수정 없음).

## 내 컴퓨터에서 해 보기 (개발용, 선택)

Node.js 20 이상이 필요합니다.

```sh
npm install
echo "APP_PASSWORD=test1234" > .dev.vars
npm run dev          # http://localhost:8788 , 비밀번호 test1234
npm test
```

`wrangler.toml` 파일은 만들지 마세요. 있으면 Cloudflare 화면에서 DB·비밀번호 설정을 바꿀 수 없게 됩니다.

## 꼬리표 규칙

- 줄 맨 앞에 `[탁구]`를 쓰면 `탁구` 꼬리표를 가진 사람의 계획표에만 들어갑니다. 꼬리표가 없는 줄은 모두에게 들어갑니다.
- `[1부][2부]`처럼 같은 묶음의 꼬리표를 여러 개 쓰면 그중 하나만 맞아도 들어갑니다.
  `[탁구][남]`처럼 다른 묶음끼리는 둘 다 맞아야 합니다.
- 어떤 묶음(예: 남/여)의 꼬리표가 하나도 없는 사람은 그 묶음의 줄을 모두 받습니다.
- 묶음은 화면의 **참여자·설정 → 반 나누기** 탭에서 바꿉니다(처음 값은 `public/rules.js`의 `DEFAULT_TAG_GROUPS`). 묶음에 없는 꼬리표(예: `[바리스타]`)는 그 꼬리표를 가진 사람에게만 들어갑니다.
- 글자는 기본이 검정입니다. 출근·활동·장소 버튼마다 「버튼 고치기」에서 글자색(검정·파랑·빨강)을 정해 두면 그 색으로 들어갑니다(줄 맨 앞에 `^` 파랑, `!` 빨강이 붙음). 한 줄만 바꿀 땐 직접 `^`/`!`를 칩니다. 이 표시와 꼬리표는 인쇄할 때 지워집니다. (`*`, `→`는 그냥 기호. 예전 규칙으로 파랗던 줄은 불러올 때 `^`를 붙여 색을 그대로 둠)
- 날짜 칸을 다른 칸으로 끌어다 놓으면 옮기기(받는 칸에 일정이 있으면 서로 바꾸기, Ctrl을 누르면 복사), 버튼을 칸으로 끌면 그 칸에 넣기.

## 저장과 동시 편집

- 입력하고 1초 뒤 자동 저장, 상단에 「저장됨 / 저장 중… / 저장 안 됨」 표시.
- 아직 없는 달로 넘어가면 지난달 패턴으로 채운 모습만 보여 주고, 처음 고칠 때 저장합니다.
- 다른 컴퓨터에서 먼저 저장했으면 덮어쓰지 않고 「다른 분 것 불러오기 / 내 것으로 덮어쓰기」를 묻습니다.
- 고치지 않는 동안에는 30초마다 다른 분이 고친 내용을 불러옵니다.

참여자 실명은 저장소에 커밋하지 않습니다. 배포 후 참여자 화면에서 입력합니다.
